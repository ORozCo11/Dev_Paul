# QA report, 27 November 2026

Scope: four changes requested after the consultant's review, tested end to end on the dev database (MySQL) with real browser sessions per role, plus the full backend suite and a regression sweep of every role's pages.

## What was built

1. **Record Repair Work asks one question first.** The mechanic chooses *I repaired it*, *No repair needed* or *Return to Admin*, then sees only what that choice needs. The repair form, parts and files appear only for *I repaired it*. The other two show one reason box and one button.
2. **The outside-shop trip is traceable.** Approval tells the Custodian what to do next. Sending the vehicle out notifies the named tester and the Admin (with the expected return date). Receiving it back notifies the Custodian. Each person's dashboard shows their next step ("Send the vehicle to the shop", "Receive the vehicle from the shop", "Test the vehicle and write up the repair", "The shop is late: follow up").
3. **Scheduled services use the same repair page.** The mechanic's *Record Repair Work* button on a schedule opens the repair page directly (parts bought, cost, photos, or no repair needed, or return to Admin). Only starting before the due date asks first.
4. **Salvage inventory.** New page for the mechanic (Admin and Custodian read only). The Admin decommissions a vehicle, the mechanic lists the parts that can still be used, and a repair that uses parts from another vehicle takes them from this stock (stock goes down; removing the use puts it back).

## Bugs found by this testing, and fixed

- **Salvage queue returned a server error on MySQL.** The query named a column `lines`, a reserved word in MySQL. The test database (SQLite) accepted it, so the backend tests passed while the real database failed. Renamed.
- **A scheduled service opened an empty Record Repair Work page.** The page looks its job up in the work-order list, which had been loaded before the job existed. The list is now reloaded first.
- **Starting a service early gave no feedback for about 3 seconds** (the job is created on the server). A "Starting the job" message now shows.
- **Finishing or reopening a salvage list looked stale for a few seconds.** The row now updates immediately.
- **Salvage action buttons touched each other.** Spacing added.

## Known limits

- When a mechanic returns to a repair already switched to "uses parts from another vehicle", the method box must be ticked again (existing behavior: the method is chosen on each visit).
- Salvage stock is returned when a donor part is removed from a repair. If a whole ticket is hard-deleted, the stock it drew is not returned (the database removes the rows without notifying the model). Cancelling a ticket keeps the parts as used, as intended.
- The mailer and Sign in link points to `FRONTEND_URL`; see the earlier email test.

## Data

All test fixtures were removed from the dev database afterwards (vehicles, tickets, schedules, notices, salvage rows, number sequences restored).
